Entity drill-down data uses explicit Resource nodes: one entity introduction, individually annotated reference images, concept design descriptions, paired prompt text and image candidates. Each description links directly to the entity root; its prompt links to the description and its Run; Run connects its outputs back as image resources. Right-clicking a node opens/resumes a node-scoped CreateEntity session. Agent edits use `update_resource` / `update_entity_profile`, and removals use `remove_resource`; changes to upstream text/reference descriptions cancel stale pending configurations.

They do not submit image generation. The `概念图生成` canvas workflow node exposes the current plan and starts one image Run on explicit user action, reusing its exact description, prompt and references. Editing a concept description marks its paired prompt `needs_refresh`; update the prompt before generation. Appearance adjustment and three-view Run configurations retain graph approval; appearance/result adoption remains explicit.

Image nodes draw the full image; node dimensions use the source image's aspect ratio and dimensions. Double-clicking image, audio or video resource nodes opens an in-canvas preview. Video assets use the private content endpoint with byte-range playback and generated thumbnails. Canvas node titles remain complete and widen their nodes to fit.
Local Studio defaults to `STUDIO_GENERATION_MODE=mock`: it synthesizes clearly labeled preview PNG/WAV assets and runs the same prompt, reference, concept-plan approval or graph Run-approval path, and result selection transitions without calling ComfyUI or a generation model. Real execution requires explicitly setting `STUDIO_GENERATION_MODE=real`; never switch modes as part of a mock walkthrough.
