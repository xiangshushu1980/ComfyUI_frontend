## Agent and Canvas Change Handoff

The canvas is the durable business-data source. At each Agent turn, the server injects a compact Workflow frame and field-level pending deltas scoped to that Workflow; do not inject a full object snapshot by default. The server filters events against the bound Workflow's target and related nodes before they reach the Agent. The `entity_studio` `context` operation is the fixed on-demand read interface: the Agent may choose bounded scopes, object IDs, kinds, search terms and fields, while the server enforces Workflow scope and result limits. Do not rely on polling or ask the Agent to scan the full canvas. Advance the acknowledged event cursor only through the context snapshot delivered for that turn, so failed delivery and canvas edits made during the Agent turn remain pending. Mark Agent-authored writes separately so they do not reappear as user edits. The Agent should incorporate relevant changes into the user's current request while preserving each Workflow's existing confirmation boundaries.
When the user asks to refresh or sync, report only pending changes and their impact. Unchanged context remains in the existing conversation state; retrieve exact current values only when they are needed to apply the requested edit. If a delta value is marked truncated, query that object's exact fields before using it. When there are no pending changes, say so briefly.
