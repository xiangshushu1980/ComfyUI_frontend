## 1. 产品目标

无限画布是“主数据图 + 动态执行覆盖层”。用户主要在独立 PiWeb 中表达目标；Agent 调用固化的业务 Workflow，自动获取上下文、绑定输入，并把状态、中间产物和结果持续写回画布。画布用于检查、确认和纠正，不以手工编排 ComfyUI 节点为主要交互。

本阶段用两个业务过程验证架构：

- 剧本侧：整本小说导入 → 结构化分章节 → 从章节整理实体 → 逐个确认关键实体。
- 实体侧：用户手动添加参考图 → Agent 用自然语言介绍实体、建议主形象方向、汇报并确认参考图用途和项目画风 → 用户在 PiWeb 确认概念图方案 → Agent 生成设计说明与提示词并直接提交概念图 Run → 候选图成为实体资源节点 → 用户确认正式形象 → 以该形象准备三视图并由用户确认配置和效果 → 人物文字设计声音样音 → 用户试听并选择。

不一次性实现完整视频链路；视频镜头、完整声音制作和上层跨 Workflow 总编排留待后续。本阶段只为人物实体增加一条文字设计的基础声音样音，不含克隆、参考音频、情绪变体、道具/场景声音或批量制作。

## 2. 概念与职责

| 概念                     | 职责                                                          | 画布表现                                  |
| ------------------------ | ------------------------------------------------------------- | ----------------------------------------- |
| Project                  | 影片工程，承载小说、章节、场景、实体、资源及全局画风          | 最高层业务边界                            |
| Chapter / Scene / Entity | 一级长期业务对象；实体含角色、物品、道具、场景等              | 默认展开                                  |
| Resource                 | 实体介绍、带用途注释的参考图、提示词、候选/正式形象、三视图等 | 归属实体并形成输入/提示词/运行/输出关系   |
| Workflow Definition      | 固定业务流程的函数定义                                        | 不作为普通常驻节点                        |
| Workflow Run             | 一次具体调用，绑定实体、资源及配置                            | 运行期轻量覆盖，结束后弱化/折叠，保留来源 |
| Agent Session            | 有目标、连续历史与等待/恢复能力的工作会话                     | 协作层与跳转入口，不必是普通节点          |

Agent 理解目标、汇聚上下文、调用 Workflow、绑定输入、推进执行和请求确认；Workflow 提供稳定可测试的业务能力；画布呈现对象、关系、执行状态及结果；用户负责目标表达、关键确认和纠正。

Workflow 是业务流程，CLI/API/Tool/MCP 是调用入口，不能混为一谈：Agent → Tool/API/CLI → Task Workflow → 函数、模型、服务或底层 ComfyUI Workflow。开发期先稳定普通 Tool/API 和 CLI，再考虑 MCP 封装；MCP 不是 MVP 前提。

## 3. 共用能力层与固定业务流程

先以手动操作验证创建实体、更新属性、生成参考/概念图、选择版本、生成三视图等能力；Agent 调用同一套操作串联步骤，不另造一套业务逻辑。

至少提供以下业务入口（名称可在接口设计时调整）：

1. StructureNovel：导入整本原文，建立工程级来源与稳定锚点，生成可检索章节。
2. ExtractEntities：读取结构化章节，整理角色、道具、场景及关系；补充描述保持来源与推断区分。Sean 后续决定：新实体候选自动创建并标记 `ai-created`；更新既有实体和采用关系仍需逐项确认。
3. CreateEntity：汇聚实体描述、相关小说与用户手动添加的素材；按概念/形象调整 Run 分别绑定提示词与引用图。聚焦的概念图对话在用户确认设计说明、参考图用途及项目画风后直接提交；形象调整等其他 Run 仍在画布确认配置。设计说明、提示词、产出图作为实体资源节点，用户确认正式形象。
4. GenerateThreeView：从已确认形象资源自动绑定输入并生成待审阅 Run；用户确认提示词/形象输入后生成，确认结果后才推进后续声音样音。
5. 人物基础声音样音：从人物声音描述和短台词生成一条 WAV 候选；用户必须在画布试听并选择，Agent 不得代选。

参考元素搜集的具体来源、三视图底层模板/模型需实查现有能力后确定，不能把目标能力写成已实现。提示词允许固定模板与 Agent 动态生成；通常作为 Run 的版本化配置/过程记录，实体制作下钻图中则显式作为可编辑资源节点呈现。

## 4. 主数据图与动态执行覆盖层

长期关系与执行关系分别存储、查询和呈现：

- 长期数据关系：章节包含场景、场景引用实体、实体关联章节、资源属于实体；参考图与说明共同约束提示词，提示词节点连接 Run 与结果资源；资源版本与已确认来源可追溯。
- 执行关系：某次 Run 绑定的输入、步骤、中间资源、输出，以及 Run 间依赖。运行结束可折叠为历史，不能自动变成长期事实。

支持串行 `实体/资源 → Run A → 中间资源 → Run B → 最终资源` 与并行 `同一输入 → Run A/Run B → 各自结果`。底层共享 GPU 可排队执行，业务并发不等于必须同时占用 GPU。

Run 展示等待输入、执行中、等待确认、完成、失败等业务状态，并可映射更细执行状态。运行时用标记、动态图线、进度图标或动画轻量展示；点击展开输入绑定、参数、步骤、中间结果、日志和输出。结束后弱化/折叠，来源不能删除。

Agent 可修改尚未提交的当前输入绑定，并记录变更；实际提交形成不可变执行快照。提交后的输入调整形成新的版本/子 Run，不能改写已发生的执行历史。

默认展示章节、场景和实体。点击章节聚焦/高亮关联场景与实体；点击实体展开其资源。候选图片尽量铺开。规模增长以缩放、聚焦、过滤和弱化历史保持可读性。

## 5. Workflow Session 与独立 PiWeb

第一阶段以业务 Workflow 为入口，默认一个 Workflow 工作实例对应一个连续 Agent Session，而非所有工程共用一个全局聊天，也不是每个按钮新建一次会话。

进入 Workflow 时按规则汇聚工程/章节/实体/资源引用；用户在 PiWeb 描述本次目标，Agent 动态补充上下文，调用固定流程。引用优先于复制，读取最新版本并记录实际读取版本。Session 有目标、上下文、连续历史，可推进、暂停、等待确认和恢复；明显超范围时提醒切换 Workflow。

无限画布与 PiWeb 是两个独立界面。不重写或嵌入 Agent Chat UI。画布 Workflow 入口、实体和 Run 可携上下文标识跳转，恢复或创建对应 Session；小型状态提示可显示是否工作与输出摘要。Pi Agent Backend 执行后通过业务 API/状态同步写回画布。关联使用 Project/Workflow/Session/Run 引用，不在 URL 暴露能力密钥或复制整段上下文。

## 6. 确认、授权与可靠性

- 第一阶段关键实体逐个确认；未来再扩展批量确认与自动采用策略。
- 候选正式形象由用户确认，确认后 Studio 为三视图建立待确认输入节点。不得要求用户手工接线。
- 用户点击实体节点的“开始实体制作流程”或从 CreateEntity Workflow 新建对话，即授权有限范围：最多四张概念/形象调整候选图、一个三视图、一个人物文字设计声音样音。聚焦的概念图对话先自然语言说明实体、建议主形象、逐张确认参考图用途；项目级画风缺少或未确认时先询问。用户确认设计方向、参考图用途、补充信息和画风后，Agent 生成设计说明与提示词节点并直接提交概念图 Run。形象调整仍使用画布配置确认；Run 提交后的快照不可变。每张图片作为实体资源节点，结果及正式形象仍由用户确认。Agent 对关键信息不确定时可在 Pi 对话询问，等待回答后继续。已确认的声音描述和样音台词保存到 Workflow Session；用户确认三视图结果后，Studio 自动启动一次声音 Run。未授权的额外生成或无限重试不在范围内。
- 手动 UI 与 Agent 共用事务、校验和幂等操作；未知提交不能自动重投。恢复不能重复生成或重复创建资源。
- 保存来源锚点、读取版本、执行输入快照、Workflow 定义版本、参数、Session/Run 身份、中间产物与输出来源。
- 场景局部状态不覆盖全局身份；动态执行绑定不任意修改长期知识图谱。
- 延续独立私有数据/媒体、共享 ComfyUI 单实例、资源租约和产品 Agent/开发 Agent 身份隔离。精确工作区信任不扩展为默认自动信任。

## 8. MVP 验收

1. 整本小说导入后生成章节节点，章节有可检索正文与来源锚点。
2. 从指定章节提取候选实体和关系，在画布出现；关键项逐个确认为正式实体。
3. 从实体创建 Workflow 进入/恢复独立 PiWeb Session，Agent 自动读取相关小说、实体与资源；用户无需逐项手动拼上下文。
4. Agent 自动绑定输入并启动固定 Concept Run；画布实时呈现轻量状态、中间产物及全部候选图。
5. 用户确认正式形象，决策与版本可追溯。
6. Agent 自动绑定正式形象启动 ThreeView Run，产出正面/侧面/背面等视图并作为实体资源展示。
7. ThreeView 成功后，为人物实体生成一条文字设计声音样音；画布提供试听，用户选择后才设为当前人物声音。
8. Run 完成后弱化/折叠；点击 Run/资源可追溯输入、Workflow 版本、参数、执行链路和输出。
9. 点击章节聚焦相关场景/实体；点击实体展开资源。长期关系不被执行临时连线污染。
10. Session 在关键确认点等待、确认后继续，刷新/重连恢复同一会话和 Run；幂等与未知提交测试确保不重复执行。
11. 共用操作同时可由手动 UI 与 Agent 调用；串行及并行 Run 关系可验证。共享 GPU 的排队不伪报并发执行。

验收目标是证明“对话表达目标 → Agent 调固定 Workflow → 画布持续呈现 → 用户关键确认/纠正”的闭环，而非先覆盖完整影片生产。

## 9. 保持开放的设计项

Run 结束后默认隐藏/微型来源标记/按时间弱化的具体方式；Run 详情字段及底层 ComfyUI 跳转；布局分区算法；大规模过滤/聚焦；提示词最终资产模型；何时引入跨 Workflow 上层编排 Agent。这些不冒充已定稿；在满足 MVP 和来源可追溯的前提下形成可审阅方案。

## 10. 用户确认的实体制作边界（2026-10-08）

- “开始实体制作流程”这个明确入口动作即本次有限生成授权；Agent 不再要求重复授权。授权额度最多四张概念/形象调整候选图、确认主形象后一个三视图、用户确认三视图结果后一个人物声音样音。
- 文字设计声音只适用于人物。Agent 可先在 Pi 对话澄清声音特点和样音台词；不使用参考音频/声音克隆。
- 样音必须在画布试听，并由用户选择为当前人物声音。其他声音制作留待后续。

## 11. 实体下钻图与节点化素材编辑（2026-10-08）

- 实体下钻图展示实体介绍节点、多张独立参考图节点、每张参考图的用途描述、Qwen Image 2.1 概念提示词节点、概念候选图节点、已选主形象、三视图提示词/结果，以及对应的 Workflow Run。
- 概念提示词由 Agent 综合实体介绍、每张参考图的图像内容和用户标注用途写成；提示词节点连向其引用图，Run 连向提示词/输入及生成结果。三视图只绑定已确认的主形象和三视图提示词节点。
- 节点右键可新建或续接以该节点为上下文的 Agent 对话。Agent 用 `update_resource` 或 `update_entity_profile` 更新现有节点；更新待确认提示词时，同步修改当前待执行 Run。参考图说明或实体介绍发生变化时，旧待确认 Run 取消，Agent 应重新编写提示词并准备新的 Run。
- 用户可编辑并保存参考图的用途描述；修改的是当前画布资源节点。可从概念候选选择一张成为主形象，再由 Studio 准备三视图 Run。
- 图片节点直接显示原图，并按原图宽高比和尺寸调整节点；音频、图片和视频节点双击后在画布内预览/播放，视频可拖动播放进度。节点标题完整显示，并按标题宽度展开。
