## Current behavior

The root view is `WorkflowStudioView.vue`. Its **Creation Graph** projects chapters, scenes, entities, pending candidates, resources and Workflow Runs. A separate Agent Workflow monitor projects the film project, PiWeb workspaces, Workflow definitions and Workflow conversations as linked view nodes; these are not duplicate business records. Active and waiting-confirmation Runs appear as nodes connected to their inputs and outputs; completed Runs are collapsed by default and accessible through history and the monitor. Chapter focus selects related entities; concept and three-view images expand on the canvas. Layout uses compact category columns; view scale/offset persist privately. This is the initial layout choice, not a large-project performance claim.

`server/workflows.mjs` owns StructureNovel, ExtractEntities, CreateEntity and GenerateThreeView. HTTP, `scripts/sean-studio/workflow.mjs`, manual import/reference/confirmation controls and the bound Pi tool use these operations. Workflow definitions are versioned capabilities; runs hold immutable input revisions, parameters, child runs and output references. Data relations remain independent of execution relations.

Novel import accepts text/Markdown and deterministically recognizes Chinese chapter headings, Chapter headings and Markdown headings. Chapters retain source offsets, paragraph anchors and hashes. This is structural splitting, not an AI rewriting algorithm. Compatible legacy chapters keep their IDs; superseded duplicates remain in history. ExtractEntities reads source text through audited, paginated tools and submits proposals. Individual human confirmation preserves earlier endpoint mappings and creates chapter/entity relations. Scene state continues to use entity_use without overwriting identity.

The canvas novel-import form and the `StructureNovel` Agent operation both call `Workflows.structure`, so they create/read the same project source and chapter records. The form sends the full novel text to that project operation directly. PiWeb Workflow context is a separate conversation: it receives source/chapter references and retrieves actual text with audited `read_chapter` or `read_source` calls; the full novel is not copied into every prompt.

CreateEntity collects user-added image/text references and automatically binds target/context. A human grants at most four concept/appearance candidate images and optionally one downstream three-view, with expiry and entity revision checking. Each image operation creates a pending Workflow Run containing an immutable prompt and reference asset/hash snapshot. The Studio graph confirmation endpoint is the only operation that creates child executions or consumes the grant. Formal appearance confirmation records the selected asset and prepares a pending fixed three-view Run bound to that appearance. Its configuration and image result each need graph confirmation. The agent cannot confirm image results. Entity prompt rules and prior-project three/four-panel references are maintained in [the entity-creation skill](../../pi/skills/entity-creation/SKILL.md). Studio currently uses the direct ComfyUI Qwen encoder; the separate official Qwen Prompt Enhancer is not called. The four-panel face/front/back/side prompt is reference-only; the active workflow remains three-view.

Entity image removal is a soft-delete operation that preserves Runs and audit history; removing the last candidate also removes its associated prompt/brief. A limited resource removal route additionally supports orphaned concept/appearance/three-view brief and prompt text, and rejects removal while that Run still has active image outputs.

Generated assets retain source asset IDs, child Run IDs, business Run IDs, graph hashes and parameters. Native snapshots are compiled from real registered-node templates and available read-only. PNG references are content-addressed in the private store; thumbnails are genuine cached images bounded to 384 pixels.

Agent conversation remains in independent Pi Web. Each Workflow/target scope resumes its own continuous, clearly named session; sessions for new bindings in one Studio project share a readable project-level PiWeb workspace. Existing bindings retain their prior workspace path so an update does not silently invalidate previously granted trust. Automatic context uses live references, not copies of the full novel. Pi Web intentionally hides idle transient sessions: after exact workspace trust, the bridge verifies the extension tools and binding, records a guarded read-only initialization turn when needed, and checks the exact session's presence in the native catalog before navigation. Failed launch never falls back to the Pi Web root or an empty conversation. Initialization cannot generate or adopt anything. Workspace trust remains exact and explicit; a new shared project workspace may need one trust action.

### Concept branches with stable numeric IDs (2026-10-13, Owner: Sean)

An entity can own multiple independent concept-image branches. Each branch receives a positive, monotonically allocated `conceptId` (`1`, `2`, `3`, …), persisted on its description, paired prompt, generation Run and generated image resources. Existing branches without a stored number receive a deterministic display number from creation order; removed branches keep their number reserved. New concept conversations create separate branches, while a repeated save in the same conversation updates that conversation's branch. `prepare_concept` accepts an explicit `conceptId` to target an existing branch; it rejects unknown IDs instead of silently creating or changing another branch.

Pi target context includes the branch number and pairing metadata. Agents list branches by number and must select that exact branch when the user asks to revise one; they read only its description and paired prompt. The canvas labels branch resources and generation actions by number. Editing a description refreshes only its paired prompt, and the inspector's prompt-refresh action opens the session for that same branch. Generation carries the branch number into its immutable Run and candidate resources.
