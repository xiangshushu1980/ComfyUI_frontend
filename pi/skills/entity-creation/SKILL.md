# Character entity creation

Owner: Sean. Runtime interaction draft; validate after a real end-to-end character run.

Use only in the bound `CreateEntity` workflow. The entity drill-down graph contains the entity introduction, separate manually-added reference image nodes with per-image usage descriptions, prompt nodes, image candidates and Runs. Launching this workflow authorizes up to four generated concept/appearance images total, one three-view image after appearance confirmation, and one text-designed character voice sample after three-view confirmation. Never ask for generation authorization again. The user confirms each image Run configuration in the entity graph before submission and confirms image results in the graph. Never confirm a prompt, reference set, or image result on the user's behalf.

When workflow context reports `generationMode: mock`, this is a full interaction rehearsal. Prompt editing, reference selection, Agent tool calls, Run confirmation, candidate selection and downstream stage transitions behave normally, while outputs are deterministic local preview media. State clearly that images and the audio tone are simulated and were not generated by Qwen, Breeze, ComfyUI, or another model. Never infer visual quality or character voice quality from mock outputs; use this mode to validate interactions and state transitions only.

## Image workflow

1. Read the current Workflow context. Inspect the entity introduction and available image resources. References are added manually by the user; do not search for, invent, or import reference images. Each reference node's `description` says what to borrow from it. Use `view_image` on relevant image assets before writing a prompt.
2. For each concept proposal, write a concrete Qwen Image 2.1 prompt from the entity introduction, inspected reference images, and their usage descriptions. Select this Run's ordered `referenceIds` from the entity's manually-added reference assets. Call `generate_concepts` with `prompt`, optional `count` (default 2), and `referenceIds`. Studio creates a visible prompt resource node and a pending configuration Run connected to the source nodes; it does not submit generation. Tell the user the Run is ready for prompt/reference confirmation and wait. Do not claim a render is running until the Run status changes to `running`.
3. The user may right-click an entity, reference, or prompt node to open a new or existing Agent session scoped to that node. When asked to edit one, use `update_entity_profile` or `update_resource` with its current revision. Updating a reference description or entity introduction cancels a pending Run that used it; rebuild the prompt and prepare a fresh Run. Editing a prompt node while its Run awaits approval updates that same node and the pending Run configuration. Wait for the user to confirm the configuration in the graph.
4. Once candidate image resources appear in the entity drill-down graph, inspect them and explain what works or needs adjustment. The user chooses one concept image as the formal appearance or asks for another iteration. If adjusting, use `prepare_appearance_adjustment` with a new prompt and that iteration's own `referenceIds`; a prior generated candidate may be included as a reference asset. Count all concept/appearance images against the shared four-image grant.
5. Do not call `generate_threeview` yourself. When the user confirms a candidate as the formal appearance, Studio prepares a three-view prompt node and Run from that confirmed image. The graph shows their connection. The user confirms this configuration before generation. After its output appears, inspect it and wait for the user to confirm the three-view result in the graph. If it needs revision, discuss the next step with the user; do not resubmit the one-use three-view grant.

## Voice sample

6. If the character's voice qualities or sample wording are unclear, ask in PiWeb and wait. Save the agreed text with `set_voice_design`. This is text-to-speech design only: no reference audio, cloning, emotion variants, props, or scene sounds. Studio starts the one authorized sample only after the three-view result is confirmed.
7. The voice output is a candidate. Its resource node can be double-clicked to listen in an in-canvas preview; the node also keeps the audio controls in its property panel. Never select or confirm the voice yourself; wait for the user's explicit choice.

Keep workflow progress in Studio Runs, grants, resources, and selection records, not chat memory. Report exact Run status and output IDs when useful. Before submission, update the existing prompt node when the user requests a prompt change; its pending Run updates with it. After submission, preserve the immutable Run snapshot and prepare a new Run for any further generation. Never resubmit an unknown submission; inspect the existing Run first.
